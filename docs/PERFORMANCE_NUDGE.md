# AIBox 性能引导设计

> 用户首次聊天后，应该/不应该弹什么提示？怎么提示？

---

## 当前方案（v2，已实现）

**核心思想**：从"硬件维度"判断 → 升级为"模型维度 + 硬件维度双因子"判断

触发条件：**"用户在跑小模型，速度却显著低于合理水平"** → 说明加速路径没走通 → 提示

### 提示文案（按用户要求）

```
┌────────────────────────────────────────────────────┐
│ 当前 小型 模型仅 5.2 tokens/s。                    │
│ 下载配套的 GPU 或 NPU 后端模块，速度也许会更快。  │
│         [前往插件市场]      [永不提示]              │
└────────────────────────────────────────────────────┘
```

注意文案用了"也许会更快"而非"将更快"，避免给用户硬承诺（实测可能因模型格式、量化方案差异达不到预期）。

### 触发判定矩阵

| 模型参数量 | CPU 合理 tps | 触发门槛（<50% 合理） | 加速预期 tps |
|----------|-------------|---------------------|--------------|
| < 1B (TINY) | 30 tok/s | < 15 tok/s | 80 tok/s |
| 1B~3B (SMALL) | 15 tok/s | < 7.5 tok/s | 60 tok/s |
| 3B~7B (MEDIUM) | 7 tok/s | < 3.5 tok/s | 30 tok/s |
| 7B~13B (LARGE) | 2.5 tok/s | < 1.25 tok/s | 12 tok/s |
| > 13B | — | 不触发 | — |

### 推荐后端策略

| 设备情况 | 推荐 |
|---------|------|
| 骁龙 V73~V81 | NPU (Hexagon 插件) |
| 非 Hexagon + 支持 Vulkan | GPU (Vulkan 插件) |
| 都不支持 | 不提示（避免无意义打扰） |

### 不触发场景

- 用户已点"永不提示" → 永久禁用
- 7 天内已提示过 → 冷却期内
- 当前推理已用 NPU → 已在加速
- 模型 > 13B → NPU 也救不了
- 模型参数未知 → 保守不提示
- 已装 Hexagon 插件但还慢 → 应走诊断机制而非 nudge
- 实际 tps ≥ 合理水平的 50% → 速度在合理范围

## 设计演进史（保留以备参考）

### v1 方案：仅看硬件（已废弃）

```
首次推理完成 → 检测设备有 V75 但未用 → 提示
```

**为什么废弃**：
- 误伤率高：用户跑大模型本来就慢，提示"用 NPU"无意义
- NNAPI 已内置：骁龙设备开箱就有 NPU 加速，提示词不准确
- 营销感强："闪电般的速度"是空话

### v2 方案：模型 + 硬件双因子（当前实现）

```
首次推理完成 → 检测"小模型 + 慢" → 提示
```

**为什么更好**：
- 用户痛点更精准："小模型慢"本身就是异常信号
- 推荐有依据：基于模型参数量级别计算合理 tps
- 触发率低：只在真正异常时打扰用户

## 一、明确反对的设计

### ❌ 反例 1：强弹窗 "前往插件市场下载 NPU 模块"

```
┌──────────────────────────────────┐
│   ⚡ 想要闪电般的速度吗？        │
│                                  │
│   前往插件市场下载 GPU/NPU      │
│   后端配套模块                  │
│                                  │
│   [现在去]  [以后再说]          │
└──────────────────────────────────┘
```

**为什么反对**：
- 用户刚进聊天，还没聊一句就被推销，体验上是"商业 App"
- "闪电般的速度"是营销话术，没有数据支撑
- NNAPI 已内置，骁龙 8 Gen 2+ 用户开箱就有 NPU，提示词不准确
- 开源工具用户对推销最敏感，会立刻反感

### ❌ 反例 2：聊天页顶部 banner 常驻

```
┌──────────────────────────────────┐
│ ⚡ NPU 加速可用！点击启用 →    ×│  ← 常驻 banner
├──────────────────────────────────┤
│  聊天内容...                     │
```

**为什么反对**：
- 持续占屏幕空间
- 即使关闭了，下次启动还可能回来
- "狼来了"效应：常驻提示=无提示

### ❌ 反例 3：每次推理都弹

每次回答完都问"要不要加速？"
- 比广告还烦

## 二、推荐设计：基于实测的智能提示（方案 C）

### 核心原则

1. **不主动推销**：用户没聊完一句之前，不显示任何加速提示
2. **用数据说话**：只在"实测有可感知差异"时提示
3. **条件触发**：只在用户设备**真的能加速**时提示
4. **可关闭永久**：用户点击"不再提示"后永远不出现
5. **不阻塞**：用 Snackbar / 低调卡片，不用 Dialog

### 触发条件矩阵

| 设备情况 | 触发策略 |
|---------|----------|
| 非骁龙设备（无 Hexagon） | **永不提示 Hexagon** |
| 骁龙 8 Gen 2 (V73) | 提示 1 次（除非用户禁用） |
| 骁龙 8 Gen 3 (V75) | 提示 1 次 |
| 骁龙 8 Gen 4 (V81) | 提示 1 次 |
| 用户已安装 npu-snpe 插件 | **永不提示** |
| 用户已选"不再提示" | **永不提示** |
| 当前推理已经在用 NPU | **永不提示** |
| 当前推理 < 1 秒 | 不提示（差异不明显） |
| 当前推理 > 30 秒 | 不提示（说明模型太大，NPU 也救不了） |

### 提示文案

**好的文案**（基于实测）：
```
本次回复耗时 5.2s（CPU 模式）。
你设备的 Hexagon V75 NPU 未启用，启用后预计 ~0.8s。
[现在启用] [了解] [不再提示]
```

**差的文案**（营销话术）：
```
⚡ 想要闪电般的速度吗？前往插件市场下载 GPU/NPU 模块！
```

差异：
- "5.2s" 是真实数字，可信
- "0.8s" 是估算，但说明依据（V75 NPU）
- "未启用" 是客观描述，不指责用户
- "现在启用" 比 "现在去" 更动作明确

## 三、UI 形态：三种候选

### 形态 A：Snackbar（推荐）

```
┌──────────────────────────────────┐
│  AI 回复内容...                  │
│  ...                             │
│                                  │
├──────────────────────────────────┤
│ ℹ 本次 5.2s（CPU）。启用 V75 NPU │
│   可降至 ~0.8s。 [启用] [×]     │  ← Snackbar
└──────────────────────────────────┘
```

- 4 秒后自动消失
- 点击 [启用] 跳转插件安装页
- 点击 [×] 触发"不再提示"

### 形态 B：聊天页面顶部小徽标

```
┌──────────────────────────────────┐
│  ⚡ 你的设备可加速 6.5×         │  ← 低调徽标，可点击
├──────────────────────────────────┤
│  聊天内容...                     │
```

- 不主动消失
- 点击进入"性能优化建议"详细页
- 7 天后自动隐藏（避免长期干扰）

### 形态 C：设置页"性能优化建议"

```
设置 → 性能优化建议
   ↓
┌──────────────────────────────────┐
│ 你的设备：骁龙 8 Gen 3 (V75)    │
│ 当前推理速度：5.2s / 1k tokens  │
│                                  │
│ ⚡ 可加速到 0.8s / 1k tokens    │
│   通过安装 Hexagon 插件         │
│   [立即安装]                     │
│                                  │
│ 📊 性能对比                      │
│   CPU (当前)     ████████ 5.2s   │
│   NNAPI (内置)   ████ 2.5s       │
│   Hexagon V75    █ 0.8s          │
└──────────────────────────────────┘
```

- 完全被动：用户主动点进来才看
- 信息密度高：可以做完整性能对比图
- 适合"高级用户"

### 推荐组合：A + C

- **A 用于首次发现**：第一次推理完触发的 Snackbar
- **C 用于深入了解**：点击 Snackbar 的"了解"或设置页"性能优化"进入详细页
- 不用 B（顶部徽标长期占用屏幕，体验差）

## 四、不该出现在第一次聊天后的情况

| 情况 | 正确做法 |
|------|---------|
| 模型加载失败 | 显示"加载失败，原因 X"，不推插件 |
| 用户在 CPU 模式聊得正欢 | 静默，不打扰 |
| 用户是麒麟 SoC（华为） | 提示"安装 HiAI 插件可加速"（条件触发） |
| 用户是联发科 SoC | 提示"启用 NNAPI 可加速"（NNAPI 已内置） |
| 用户是非旗舰 SoC | 不提示（NPU 加速不明显） |

## 五、关键反屎山约束

### 1. 提示策略可关闭

```kotlin
// 反屎山：策略通过 DataStore 持久化，可被用户修改
interface PerformanceNudgePolicy {
    val shouldShowHexagonNudge: Flow<Boolean>
    suspend fun disableHexagonNudge()
    suspend fun reset()  // 用户点"恢复默认提示"用
}
```

### 2. 提示有冷却期

- 同一插件市场提示：每 7 天最多 1 次
- 用户点"不再提示"后：永久禁用
- 用户重置应用：恢复默认（再提示 1 次）

### 3. 触发条件可单元测试

```kotlin
// 触发逻辑必须独立成 NudgeDecider 类，便于测试
class NudgeDecider(
    private val deviceInfo: DeviceInfo,
    private val installedPlugins: Set<String>,
    private val userPreferences: NudgePreferences,
) {
    fun shouldNudgeAfterInference(result: InferenceResult): NudgeDecision {
        if (userPreferences.hexagonNudgeDisabled) return NudgeDecision.No
        if (result.npuUsed) return NudgeDecision.No  // 已经在用 NPU
        if (result.latencyMillis < 1000) return NudgeDecision.No  // 太快，无意义
        if (result.latencyMillis > 30_000) return NudgeDecision.No  // 太慢，模型问题
        if (deviceInfo.hexagonVersion == null) return NudgeDecision.No  // 非 Hexagon 设备
        if ("aibox-plugin-npu-snpe" in installedPlugins) return NudgeDecision.No  // 已装

        return NudgeDecision.Show(
            currentLatencyMs = result.latencyMillis,
            estimatedHexagonLatencyMs = estimateHexagonLatency(
                result.latencyMillis, deviceInfo.hexagonVersion
            ),
            recommendedPluginId = "aibox-plugin-npu-snpe",
        )
    }
}
```

### 4. 估算逻辑可校准

`estimateHexagonLatency()` 不是凭空给数字，而是基于：
- 设备 Hexagon 版本基准（V73: 4x, V75: 6x, V79: 8x, V81: 10x）
- 实测 CPU 性能基线
- 模型规模修正系数
- 首次提示后用户的实际反馈（"我装了插件但没快 6x"）→ 校准基准

## 六、英文/中文文案备选

### 中文（推荐）

- Snackbar: `本次回复 5.2s（CPU）。启用 V75 NPU 可降至 ~0.8s。`
- 按钮: `启用` / `了解` / `不再提示`

### 英文

- Snackbar: `Took 5.2s on CPU. ~0.8s with V75 NPU enabled.`
- Buttons: `Enable` / `Learn more` / `Don't show again`

### 禁用文案（营销感太强）

- ❌ `⚡ 想要闪电般的速度吗？`
- ❌ `释放你设备的全部潜能！`
- ❌ `立即下载 NPU 模块，享受 AI 极速体验`
- ❌ `你正在使用慢速模式，立即升级！`

## 七、对比行业实践

| App | 类似场景的提示 | 借鉴/教训 |
|-----|----------------|-----------|
| TensorFlow Lite Examples | 无任何提示 | 太克制，普通用户不知道可以加速 |
| LlamaChat (开源) | 设置页有"GPU 选项" | 静默，但用户找不到 |
| 微信小程序 | 强推各种"提升体验" | 太烦，AIBox 不要学 |
| Apple Intelligence | 系统层 NPU 切换无感 | 最理想，但 AIBox 不在系统层 |
| Stable Diffusion WebUI | 设置页 GPU 切换 + 性能基准 | 借鉴：详细对比页 |

AIBox 应该走在中间：比 TensorFlow Lite 主动，比微信克制。
